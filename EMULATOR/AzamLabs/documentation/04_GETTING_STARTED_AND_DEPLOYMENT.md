# 🚀 AzamLabs: Getting Started & Deployment Guide

> **"Deploy in 60 Seconds on Ubuntu 26 or Docker."**

This guide provides step-by-step instructions for deploying **AzamLabs** on bare-metal servers, virtual machines, and Docker containers, including the image file naming reference.

## 🏷️ Image Directory & File Naming Architecture

AzamLabs makes image management completely flexible:

```
/opt/azamlabs/images/ (or ./images/)
├── qemu/
│   └── <vendor>-<model>-<version>/              <--- Folder Name (e.g. cisco-c8000v-17.09.03a)
│       ├── system.qcow2 (or virtioa.qcow2)       <--- Primary Boot Disk
│       ├── data.qcow2 (or virtiob.qcow2)         <--- (Optional) Secondary Data Disk
│       ├── cloud-init.iso (or cdrom.iso)         <--- (Optional) Day-0 Seed ISO
│       └── azam-meta.json                        <--- (Optional) Custom RAM/CPU override
├── iol/
│   └── bin/
│       ├── cisco-iol-l3-adventerprise-15.5.bin   <--- Layer 3 Router Binary
│       ├── cisco-iol-l2-adventerprise-15.2.bin   <--- Layer 2 Switch Binary
│       └── iourc                                 <--- License Key (Auto-Generated by AzamLabs)
├── docker/
│   └── (Standard OCI Docker tags: ceos:4.30.0F, azam/frr:latest, azam/kali:latest)
└── vpcs/
    └── vpcs.bin (Built-in lightweight virtual PC binary)
```

### Disk Image File Naming Inside QEMU Folders
- **Standard Names**:
  - `system.qcow2` or `disk1.qcow2`: Primary OS boot disk.
  - `data.qcow2` or `disk2.qcow2`: Secondary storage.
  - `cloud-init.iso` or `day0.iso`: Day-0 configuration seed.
- **🧠 Zero-Renaming Auto-Detection**:
  - Downloaded a file named `c8000v-universalk9.17.09.03a.qcow2` or `vEOS64-lab-4.28.0F.vmdk`?
  - **You do NOT need to rename it!** AzamLabs automatically binds any single `.qcow2`, `.vmdk`, or `.img` file found in the folder as the primary boot disk.
  - Legacy names like `virtioa.qcow2` and `hda.qcow2` are also recognized automatically.

## 🐳 Deployment Option 1: Docker-Proof (One-Click)

AzamLabs is 100% "Docker-proof" and can be deployed in a single command on any Linux or WSL2 system with Docker installed:

```bash
# Clone the repository
git clone https://github.com/azambasha1987/AzamLabs.git
cd AzamLabs

# Launch the entire AzamLabs stack
docker compose up -d
```

Access the Studio Web UI immediately at **`http://localhost:8000`**!

## 🖥️ Deployment Option 2: Ubuntu 26 Native Host Installer (Recommended for Hypervisors)

For dedicated bare-metal servers or VMware/Proxmox VMs running **Ubuntu 26.04 LTS**:

```bash
# Run the automated host installer
sudo bash scripts/install-azamlabs.sh
```

### What the Host Installer Does Automatically:
1. Verifies Intel VT-x / AMD-V hardware virtualization support.
2. Applies optimized `/etc/sysctl.d/99-azamlabs.conf` tuning (`ip_forward=1`, `max_user_watches=1048576`).
3. Tunes the kernel **KSM (Kernel Same-Page Merging)** engine for 100:1 RAM deduplication (`pages_to_scan=1000`, `sleep_millisecs=20`).
4. Compiles the native C CPU idle governor shim `azam-iol-shim.so`.
5. Sets up the Python virtual environment and symlinks `/usr/local/bin/azam`.
6. Configures and starts the systemd service (`azamlabs.service`).

## ⚡ The `azam` CLI Power Tool Cheat Sheet

| Command | Action | Example |
| :--- | :--- | :--- |
| `azam doctor` | Host virtualization, KSM, and environment diagnostics | `azam doctor` |
| `azam lab list` | List all stored labs, running nodes, and states | `azam lab list` |
| `azam lab create <file>` | Create and store a new lab from YAML/JSON file | `azam lab create topology.yaml` |
| `azam lab start <id>` | Start all nodes with anti-bootstorm staggered scheduling | `azam lab start prod-mesh` |
| `azam lab stop <id>` | Gracefully stop all nodes in a lab | `azam lab stop prod-mesh` |
| `azam lab wipe <id>` | Wipe ephemeral QCOW2 overlays and reset to Day-0 | `azam lab wipe prod-mesh -y` |
| `azam lab status <id>` | Show real-time telemetry, 100:1 memory savings, and ports | `azam lab status prod-mesh` |
| `azam convert import <file>` | Ingest CLAB, CML, EVE, GNS3, P2V config, or .azaml bundle | `azam convert import spine-leaf.clab.yml` |
| `azam convert export <id> <fmt>` | Export lab to `clab`, `cml`, `eve`, `gns3`, `azaml`, or `yaml` | `azam convert export prod-mesh cml -o out.yaml` |
| `azam console <id> <node>` | Retrieve desktop URI (`telnet://`) and connection port | `azam console prod-mesh Spine-01` |
| `azam day0 <id> [-r proto]` | Auto-assign IP plan and render Day-0 initial configs | `azam day0 prod-mesh --routing ospf` |
| `azam version` | Display platform build version and clean-room assurance | `azam version` |

## 🔄 Universal Lab Import Quickstart

AzamLabs allows you to open labs from ANY platform with zero manual conversion:

1. Open **AzamLabs Studio** in your browser at `http://<your-server-ip>:8000`.
2. Simply **drag and drop** any lab file directly onto the canvas:
   - Containerlab: `my-topology.clab.yml`
   - Cisco CML 2.x: `cml-lab.yaml`
   - EVE-NG / PNETLab: `enterprise-bgp.unl`
   - GNS3: `sdwan-project.gns3`
3. AzamLabs auto-detects the format, converts the schema, and renders the interactive topology with vendor icons instantly!
4. Click **"Start All"** to boot the lab with anti-bootstorm staggered startup.
